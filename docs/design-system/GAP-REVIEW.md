# 设计规范补充清单

审查日期：2026-11-06。基线：本地 v1.0.0 的 tokens、组件目录、可交互示例、业务实现与验收文档。本次是覆盖度审查，没有新增 UI 实现或重新执行浏览器验收。

当前约束：只在本地修改与验证，GitHub 写入和部署等待用户新的明确指令。

## 结论与判断口径

目前已有核心参数、部分公共组件、页面清单和业务原则。完整度的主要缺口是：组件级的尺寸/状态/行为规范、布局示意和异常边界，而不是重新确定品牌视觉。

三类状态分别记录：
- **已有，待显式展示**：值或行为已存在，但规范页没有独立可视示例/用途表。
- **实现分散，待归纳**：业务页面可用，但没有一致的组件契约与验收要求。
- **待实现或验证**：不能仅补一段说明就标为已支持。

## 3. 交互状态

当前是全局状态文字表及局部示例，仍需建立“组件 × 状态”矩阵，并对不适用项标记 N/A。

- 默认、悬浮、按下、选中、聚焦、禁用、只读、加载、成功、错误：给出并排视觉示例和触发/退出条件。按下、只读、成功反馈尚未完整展开。
- 同时发生的状态：禁用时不触发 hover 动作；选中时悬浮如何显示；错误状态获得焦点如何显示；加载时能否取消。各组件应独立说明。
- 拖动：拖动源、放置目标、不可放置、跨行/边界、取消、键盘替代、保存失败。触屏拖动未通过本版验证。
- 滚动：页面与卡片的滚动归属、固定头/底栏、条目定位、滚动条显示、不因滚动条跳宽。
- 键盘：Tab 顺序、方向键、Home/End、Enter/Space、Escape；弹窗打开/关闭的焦点位置。树和部分旧浮层不能标注为已完整支持。
- 加载/失败：区域加载与整页加载区别、保留旧内容或占位的策略、重试入口、重复提交限制；无需为了凑状态给所有组件添加骨架屏。

优先级：P0。现有 51 组测试只证明其记录范围，不覆盖上述全部组合。

## 4. 页面布局

当前有头部/侧栏尺寸、部分断点文字和 14 个页面条目；需要补可标注、可比较的布局模板。

1. 工作台：三栏宽度分配、卡片上下对齐、左右栏独立滚动，以及中窄屏的堆叠顺序。
2. 导航：侧栏展开/折叠、头部与页面标题、浮动切换入口及层级。
3. 列表/详情：筛选区、表格区、分页区、目录区、详情/抽屉的宽度与高度关系。
4. 门户资讯：主次栏比例、Banner 比例、新闻卡片宽度、轮播留边和提醒区域。
5. 适配矩阵：区分“测试视口”和“响应式断点”。1920/1440/1280 是已测视口，1500/900 等才是现有 CSS 分支；逐页确认最小可用宽度、重排与横向滚动策略。
6. 长内容/空数据/大字号下的布局边界；不把规范页 390px 通过当成整个业务系统支持移动端。

优先级：P1；会造成遮挡/无法操作的具体问题升为 P0。

## 建议补充批次

1. **第一批：组件与状态**。补七类缺少完整规范的组件，以及统一状态优先级和可交互例子。完成标准：每项有结构、尺寸、状态、行为、代码入口、验收点。
2. **第二批：基础样式可视化与布局模板**。补品牌/背景/边框/阴影、间距标注和桌面适配矩阵，统一文档与实际页面。
3. **第三批：六类业务组件专页**。给出字段、状态、边界、行为与实际场景；需要业务决策的条目保持待定。
